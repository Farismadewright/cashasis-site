# Native Work publishing runner
Use native ChatGPT Work tasks with the installed skill and current connected tools. Official docs: https://learn.chatgpt.com/docs/automations (verified 2026-10-13). Cloud tasks can use skills/plugins and uploaded context; they do not preserve scratch/worktrees. Reconstruct source, assets and records from GitHub every run. Do not require new AI/API credentials. Use built-in search, writing and imagegen, plus the locked renderer. No Windsor, external generation subscriptions, Zapier or Make.
Proposed cadence: morning daily, flexible 8:00 AM America/Chicago (execution window approximately 8–9 AM); weekly report Monday morning. Owner specified daily frequency, not an exact hour; use flexible scheduling. Before scheduling a production task, every required connected app must pass harmless reads; no schedule may promise missing access will work later. A separate paused preflight task may inspect only already-working GitHub/Netlify/GHL. Do not label a configured or queued task as a proven unattended production run. Verify scheduler results, run records and exact live deployment after an actual test.
For every production run: fetch durable state and latest main, test required integrations, stop on missing analytics/mobile/conversion gates or quotas. Fetch runtime branch automation/blog-publisher-runtime; create from main if absent. Acquire the runtime lease with GitHub Contents API create_file/update_file on runtime-state.json. For update_file use the freshly fetched content blob SHA; a concurrent writer changes that SHA and the old write must be rejected. Include an incrementing fence, unique runId, issuedAt and expiresAt. Never force or retry a rejected write without refetching. Contents API lease advancement was verified and a stale SHA write was rejected with HTTP 409 in the isolated validation branch. Ref-update expected_sha testing returned an ambiguous upstream error, so use the verified Contents API lease. Lease includes runId, date, expiry (≤2 hours) and fencing generation. On compare-and-swap conflict stop/refetch; do not overwrite another lease. Reserve intended slugs/intent keys/daily slots before imagegen, counting reserved/preview/publishing/published/unknown toward 3. Only explicit recorded HOLD releases a never-published reservation; an ambiguous deployment never frees a slot. Recheck lease and latest main before each main update; a stale worker may not publish even if its content is ready. Use release_gate.py plus manual native editorial/factual/visual review; pass labels require evidence.
Use a fresh content-only PR after duplicate/content checks. Include only new article/image/social/public-safe records and generated allowlist; protect layouts/CSS/forms/functions/analytics settings from routine runs. Infrastructure code changes require their own tested implementation scope. Respect branch checks and connector permissions. User authorizes routine publication after activation; do not ask article by article. Verify candidate preview and exact commit, then merge using normal checks, verify production ready, HTTP/canonical/images/CTA/sitemap/RSS and record result. A failed deploy leaves previous production; unresolved regressions stop further releases and use fix-forward.
On budget/quota limit, unavailable built-in imagegen or read-only analytics access, HOLD; never switch to paid API, another provider or buy credits. Initial external API spend allowance is $0. Native plan/Netlify usage remains subject to existing allowances; no guaranteed unlimited throughput. Read approved state rather than assuming a paid plan budget. Never persist credentials or raw GHL content.
Weekly read-only report: aggregate published/held and comparable GSC/GA windows, indexing, queries, organic landing sessions, unique seller leads and attribution coverage, seller-origin topics, decay/cannibalization and next refreshes. Use weekly_report.py; unavailable stays null. No social publishing.
