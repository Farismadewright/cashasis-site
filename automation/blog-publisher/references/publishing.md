# Release state and workflow
Durable repository targets: automation/blog-publisher/state.json, records/<slug>.json and topic-ledger.json. Missing state means unattended OFF. Initial state:
{"mode":"validation","unattendedProduction":false,"dailyCap":0,"templateApproved":false,"workflowPassed":false,"conversionPassed":false,"runnerEnabled":false}

Validation: fetch main, isolate branch, baseline build. Create one harmless test article/image; verify draft exclusion, then expose it only on validation branch. Full build and output checks; protected sources byte-identical to main. Push branch and open draft PR labeled validation only/do not merge; verify exact commit's Netlify noindex preview. Check HTTP/assets, card/article desktop/mobile, SEO, FAQ, CTA parameters, sitemap/RSS and noindex header. Do not merge test fixtures or submit fake seller leads to live GHL. Validate conversions through sanctioned test environment or authorized tagged test.

Activation requires successful exact-commit preview evidence, one-time new-template approval required by repository rulebook, provider credentials and approved cost ceiling, secure runner, durable idempotency/locking, alert destination, confirmed conversion attribution and owner authorization for unattended mode. Never mark pass from instructions or code presence. Installation must not enable cron.

Activated production: refresh main/state; acquire durable lock, fail closed if unavailable. Reserve stable intent/slug IDs before paid generation, check published/pending records and bound retries (one corrective retry then HOLD). Enforce America/Chicago daily count and approved USD ceiling including images/builds; unknown costs cannot pass budget gate. Start ≤3/day for 14 days; ≤5 after review; 10 needs owner tier activation and quality/indexing/conversion evidence. Cap failed attempts too.
Stage content-only PR, validate exact commit, preserve branch protection/merge process; never force-push main or blanket auto-merge. If main changes, recheck overlap/build. Verify production and record commit/deploy after merge; stop next releases on failure. Failed deploy leaves live site unchanged. Fix published regressions forward with corrective/revert commit preserving unrelated work. Send alerts only through authorized channel/recipients.
A skill guides Work execution; it does not install a paid provider or execute while idle. A separately configured external runner or supported automation is required for unattended execution. Report actual capability.
